01 — Proceso

Pipeline de integración
de datos

Los seis datasets pasan por un proceso ETL reproducible que normaliza coordenadas, resuelve conflictos espaciales y genera la capa de barrios fusionada barrios_merged.geojson.

01
⬇️
Ingestión

Descarga automatizada de los seis datasets vía WFS/CSV/GeoJSON desde los portales oficiales. Validación de checksums y detección de cambios incrementales.

02
🔄
Normalización

Reproyección a EPSG:4326. Limpieza de coordenadas inválidas, duplicados y registros fuera del polígono de la ciudad de Madrid. Codificación UTF-8 uniforme.

03
🔗
Enriquecimiento

Cruce espacial: cada barrio recibe el recuento de árboles, la densidad de refugios por km², el porcentaje de mayores y la longitud de calle con sombra.

04
📐
Índice de calor

Combinación ponderada de cuatro sub-índices normalizados (0–10) por barrio: LST (40 %), NDVI inverso (25 %), vulnerabilidad demográfica (20 %), déficit de refugios (15 %).

05
🧮
Enrutamiento

Grafo de calles ponderado por temperatura de tramo, presencia de sombra y accesibilidad. Algoritmo A* con heurística de mínima exposición térmica acumulada.

06
🌐
Publicación

GeoJSON fusionado publicado en /public/data/. API Next.js para consultas de ruta. Repositorio público en GitHub con licencia MIT.

03 — Modelo

El índice de calor:
cómo se calcula

Cada barrio recibe una puntuación entre 0 (fresco) y 10 (muy caluroso) combinando cuatro dimensiones normalizadas.

Fórmula del índice compuesto
ÍNDICE = 0.40 × LST_norm + 0.25 × (1 − NDVI_norm) + 0.20 × VULN_dem + 0.15 × DEF_refugios
LST_norm (40 %)
Temperatura superficial del suelo (Land Surface Temperature) normalizada por barrio. Proxy de isla de calor urbana.
1 − NDVI_norm (25 %)
Inverso del índice de vegetación. Un NDVI bajo (poca vegetación) contribuye positivamente al índice de calor.
VULN_dem (20 %)
Porcentaje de población mayor de 65 años en el barrio, normalizado al máximo de Madrid. Escala de riesgo humano.
DEF_refugios (15 %)
Déficit de cobertura de refugios climáticos: proporción de calle a más de 300 m de cualquier refugio.

05 — Tecnología

Capacidades técnicas
del sistema

Una pila moderna, ligera y desplegable en cualquier proveedor cloud que soporte Next.js o Node.js estático.

🗺️
Datos geoespaciales

Procesamiento con GeoPandas y GDAL. Cruce espacial vía PostGIS. Exportación a GeoJSON optimizado con Tippecanoe para visualización web.

GeoPandas PostGIS GDAL Tippecanoe
⚡
Enrutamiento climático

Grafo OSM complementado con atributos climáticos propios. Algoritmo A* ponderado por temperatura, sombra y accesibilidad. Tiempo de respuesta <2 s para rutas <5 km.

NetworkX OSMnx A* Python
🖥️
Frontend interactivo

Aplicación Next.js 15 con React Server Components. Mapa Leaflet con capas GeoJSON. Visualizaciones Recharts. Diseño mobile-first, accesible (WCAG AA) y sin dependencias de cookies.

Next.js 15 TypeScript Tailwind v4 Leaflet Recharts
🔄
Actualización de datos

Pipeline ETL ejecutado en GitHub Actions. Detecta cambios incremetales en los portales de datos abiertos y regenera únicamente los barrios afectados cada 30 min en verano.

GitHub Actions ETL incremental Cron jobs Vercel
06 — Transparencia

Código abierto y
reproducible

Cualquier persona o institución puede auditar, replicar o adaptar el modelo a otro municipio. Todas las dependencias son software libre.

Repositorio público en GitHub

El código fuente completo — pipeline ETL, algoritmo de enrutamiento y frontend — está publicado bajo licencia MIT. Cualquiera puede hacer fork y adaptar el modelo a otra ciudad.

Datos con CC BY 4.0

Todos los datasets fuente tienen licencia abierta del Ayuntamiento de Madrid. Los datos procesados generados por el modelo se publican con la misma licencia CC BY 4.0.

Documentación técnica

Cada paso del pipeline está documentado con docstrings, tests unitarios y un notebook Jupyter de ejemplo que permite reproducir el índice para cualquier barrio de Madrid.

Premio Reutilización de Datos Abiertos 2026

Madrid Refugio nació como proyecto cívico para demostrar que los datos abiertos del Ayuntamiento, bien integrados, pueden salvar vidas durante las olas de calor. Candidatura en la categoría Impacto Social. Todo el código y los datos son públicos desde el primer día.
